# Сборочный сервер на Proxmox

Что он делает: следит за GitHub, и как только там появляется новый код —
проверяет его (типы, тесты) и **сам отправляет обновление вам на телефоны**.
Если менялась нативная часть, по воздуху её не доставить — тогда сервер
собирает новый `apk` и говорит, что нужна переустановка.

От вас после настройки не требуется ничего.

**Чего сервер не может:** собирать для iPhone. Apple разрешает подписывать
приложения только на macOS. Айфон остаётся на ноутбуке: `npm run setup:ios:release`.

---

## 1. Контейнер в Proxmox

В веб-интерфейсе Proxmox: **Create CT**.

- Шаблон: **Debian 12**
- Cores: **4** (меньше — сборка apk будет идти час)
- Memory: **8192** МБ
- Disk: **40** ГБ
- Network: DHCP
- **Features → Nesting: включить** (без этого сборка Android не запустится)

Запустите контейнер и войдите в него: кнопка **Console** или по ssh.

## 2. Установка

```bash
apt-get update && apt-get install -y git
git clone https://github.com/kafiberlass/km.git /tmp/km
bash /tmp/km/server/install.sh
```

Минут двадцать: скачивается Android SDK, он большой.

## 3. Ключи

```bash
nano /etc/km/env
```

Заполнить три строки:

- `EXPO_TOKEN` — expo.dev → аватар → Account settings → Access tokens → Create token
- `EXPO_PUBLIC_SUPABASE_URL` и `EXPO_PUBLIC_SUPABASE_ANON_KEY` — те же, что в `.env`
  на ноутбуке (`cat ~/km/.env`)

Сохранить: `Ctrl+O`, `Enter`, `Ctrl+X`.

Без ключей Supabase сервер отправит сборку с выдуманными друзьями —
ровно та поломка, которую мы уже ловили.

## 4. Проверка

```bash
systemctl start km-watch.service
journalctl -u km-watch -n 50 --no-pager
```

Должно быть видно: «смотрю ветку», «приехало: …», «проверяю типы»,
«прогоняю тесты», «отправляю обновление».

Дальше он делает это сам каждые две минуты.

## Как посмотреть, что происходит

```bash
journalctl -u km-watch -f        # живой журнал
systemctl list-timers km-watch   # когда следующая проверка
```

## Как забрать apk

Сервер раздаёт готовые файлы по адресу `http://<адрес-сервера>:8088`.
Открывается прямо с телефона, ставится оттуда же.

Адрес сервера: `hostname -I`.

## Сообщения в телеграм (необязательно)

Чтобы сервер писал вам, когда обновление ушло:

1. В телеграме найдите **@BotFather** → `/newbot` → получите токен.
2. Напишите своему боту любое сообщение.
3. Откройте `https://api.telegram.org/bot<ТОКЕН>/getUpdates` и найдите там
   `"chat":{"id":123456789`.
4. В `/etc/km/env`:

```
KM_NOTIFY_URL=https://api.telegram.org/bot<ТОКЕН>/sendMessage?chat_id=<ID>&
```

Адрес заканчивается на `&` — сервер дописывает к нему текст сам.

## Если что-то пошло не так

| Что видно в журнале | Что это значит |
|---|---|
| `нет EXPO_TOKEN` | не заполнен `/etc/km/env` |
| `нет связи с GitHub` | контейнер без интернета |
| `типы не сходятся` / `тесты не прошли` | код сломан — обновление **не** ушло, и это правильно |
| `обновление не отправилось` | протух `EXPO_TOKEN` либо кончился интернет |
| `apk не собрался` | чаще всего мало памяти или выключен Nesting |

Сервер никогда не отправляет непроверенный код: если тесты не прошли,
он останавливается и ждёт следующего коммита.
