# КМ — скелет

Гамифицированный трекер прогулок с туманом войны. Скелет под дизайн
«Design map 1.1»: карта открывается по мере ходьбы, за это капают XP,
уровни, стрик и ачивки.

**Что это и что это не.** Это не MVP, а стенд для проверки трёх вещей,
на которых такие приложения ломаются: производительность тумана, качество
фоновой геолокации и стоимость учёта покрытия. Экраны «Ачивки», «Места»
и «Профиль» сделаны ровно настолько, чтобы данные было видно.

Бэкенда нет. Всё живёт в SQLite на устройстве.

---

## Быстрый старт

```bash
npm install
```

```bash
npm test
```

Тесты гоняют чистую логику (Меркатор, H3, фильтр GPS, XP, стрик, ачивки,
восход/закат) без эмулятора — 43 теста за полсекунды.

Для запуска на устройстве нужен **dev build**: MapLibre, Skia и op-sqlite —
нативные модули, в Expo Go они не работают.

```bash
npx expo prebuild --clean
```

```bash
npm run android
```

Проверить, что бандл собирается, можно и без устройства:

```bash
npx expo export --platform android --no-bytecode --output-dir .export-check
```

## iPhone: запуск на бесплатном аккаунте

Платить Apple $99 не нужно, пока приложение не уходит в стор. Хватает Mac
с Xcode из App Store и обычного Apple ID — того же, что на телефоне.

Подключите iPhone кабелем, разблокируйте, нажмите на нём «Доверять этому
компьютеру» — и одна команда:

```bash
npm run setup:ios
```

Скрипт (`scripts/setup-ios.sh`) проверяет окружение, ставит зависимости
(CocoaPods в том числе, если есть Homebrew), генерирует `ios/` и собирает
приложение на телефоне. Ручными остаются четыре шага — автоматизировать их
нельзя, но скрипт предупреждает про каждый в нужный момент и не даёт узнать
о проблеме после двадцати минут установки:

1. Xcode из App Store.
2. Вход в Apple ID: Xcode → Settings → Accounts → «+», затем
   «Manage Certificates…» → «+» → «Apple Development». Одного входа мало,
   сертификат нужно выпустить явно, иначе подписывать сборку нечем.
   Если он выпущен, но недействителен (`security find-identity` показывает
   `1 identities found / 0 valid`) — в связке ключей не хватает
   промежуточных сертификатов Apple, скрипт доставит их сам.
3. «Режим разработчика» на телефоне: Настройки → Конфиденциальность
   и безопасность. Пункт появляется только после первой попытки установки.
4. Доверие сертификату после установки: Настройки → Основные → VPN
   и управление устройством.

Папки `ios/` в репозитории нет намеренно: она целиком выводится из
`app.json` и `package.json`, а в гите давала бы конфликт на каждом
изменении конфига.

Цена бесплатной подписи: сборка перестаёт запускаться через 7 дней, и на
устройстве живёт не больше трёх таких приложений. Лечится повторным
`npm run setup:ios`. Между пересборками JS-изменения подхватывает
обычный `npx expo start --dev-client` — нативку трогать не нужно.

Два ограничения личного аккаунта уже учтены в конфиге, но их стоит знать,
потому что оба ломают подпись молча и непонятным сообщением:

- **`bundleIdentifier` должен быть уникальным на всю Apple.** `com.example.*`
  давно занят, поэтому в `app.json` стоит `com.kafiberlass.km`.
- **Push-entitlement (`aps-environment`) личному аккаунту не выдаётся.**
  А `expo-notifications` дописывает его в `KM.entitlements` самим фактом
  установки — плагин применяется автолинковкой, в `plugins` его перечислять
  не надо. Поэтому пакет убран из зависимостей (в коде он не использовался).
  Когда дойдут руки до напоминаний про стрик: локальным уведомлениям push
  не нужен, но вычищать entitlement придётся своим config-плагином.

Фоновая геолокация от этого не страдает: `UIBackgroundModes` лежит
в Info.plist, а не в entitlements, и с бесплатной подписью работает.

**Scene life cycle.** `plugins/withSceneLifecycle.js` дописывает в Info.plist
scene-манифест и подключает `EXExpoAppSceneDelegate`. Без этого iOS 27 SDK
не запускает приложение вовсе: процесс стартует и гаснет с «UIScene life
cycle is required for apps built with this SDK» — внешне мгновенный вылет
с чёрным экраном и выходом с кодом 0, без крэш-репорта. Всё нужное в Expo 57
уже есть, шаблон prebuild это просто не подключает; когда догонит — плагин
можно удалить.

Чего на iOS нет: аналога Lockito. Подменять координаты можно либо
GPX-плеером в дев-панели, либо через Xcode — Debug → Simulate Location.

## Кварталы

Процент открытия района («открыто 3%») не говорит ничего: непонятно,
много это или мало, и непонятно, куда идти, чтобы стало больше. Квартал —
цель с видимым краем: осталось две улицы, и он закрыт.

Квартал — та же сетка H3, только крупнее: ячейка девятого уровня содержит
49 учётных ячеек одиннадцатого, по земле это примерно 350 метров поперёк.
Прогулка минут на десять, а не на день.

**Закрытым считается квартал на 80%, а не на 100%.** Сто процентов
означало бы зайти в каждый двор и на каждый газон: коридор раскрытия
шириной сто метров покрывает улицы, но не внутренности кварталов.
Восемьдесят — это «прошёл все улицы», достижимо и ощущается честно.

Награда начисляется в момент закрытия, а не в конце прогулки: человек
только что дошёл последнюю улицу, и подтверждение должно прийти сейчас,
иначе связи между действием и наградой не возникает. Засчитывается ровно
один раз — сравнивается состояние до и после, а не проверяется «закрыт
ли», иначе XP капал бы на каждом шаге внутри закрытого квартала.

Тонкость, на которой держится согласованность: квартал точки считается
через её учётную ячейку, а не напрямую. Сетка H3 вложена не идеально,
и у точки возле границы эти два ответа расходятся — экран показывал бы
прогресс одного квартала, а счётчик вёл другой.

## Что проверять в первую очередь

1. **Откройте вкладку «Карта» → `DEV` в правом верхнем углу → `ПРОИГРАТЬ ×20`.**
   Фикстура — вечерняя прогулка вокруг Чистых прудов, 212 точек, ~2.6 км.
   Карта должна открываться коридором с мягким краем, как в макете.
2. **Подвигайте карту во время проигрывания.** Главный вопрос скелета:
   не отстаёт ли туман от тайлов при панорамировании (см. «Известные риски»).
3. **`ПРОИГРАТЬ МГНОВЕННО`** — весь трек за один тик. Проверяет XP, ачивки
   и стрик, не заставляя ждать анимацию.
4. **`DRY-RUN ФИЛЬТРА`** — покажет, сколько точек отсеялось и почему,
   ничего не записывая в базу.

Внизу карты во время прогулки выводится время сборки геометрии тумана —
это и есть метрика, ради которой скелет написан.

## Ключевое архитектурное решение

**Визуальный туман и учётный туман — разные структуры данных.**

| | Визуальный слой | Учётный слой |
|---|---|---|
| Что | обводка пути толстой линией со скруглениями | множество H3-ячеек res 11 |
| Где | `src/features/fog/` (Skia) | `src/core/geo/coverage.ts` + SQLite |
| Зачем | мягкая «тропа» как в макете | точный процент, XP, будущая серверная валидация |

Так сделано потому, что геометрический путь (`turf.buffer` + `turf.union`
по всей истории) деградирует в ноль за пару месяцев, а рисовать по ячейкам —
значит получить шестиугольные края вместо макета.

**Как туман не тормозит.** Геометрия строится один раз в локальных метрах
Меркатора. При движении карты меняется только матрица трансформации,
которая считается в воркете Reanimated на UI-потоке
(`cameraMatrixWorklet` в `src/core/geo/mercator.ts`). React при панорамировании
не ре-рендерится, стоимость кадра не зависит от длины истории.

Локальный `origin` (первая точка пользователя) обязателен: абсолютные метры
Меркатора доходят до 2·10⁷, а Skia считает во float32 — на таких величинах
трек начинает дрожать.

Питч карты выключен намеренно: перспектива требует 4×4-матрицы и ломает
постоянную ширину тропы. В макете карта плоская.

## Геолокация: что включено и что купить потом

`src/features/tracking/` содержит три реализации одного интерфейса:

- **`mock.ts`** — GPX-плеер. Инструмент разработки №1.
- **`expoLocation.ts`** — бесплатный вариант, работает из коробки.
- **`transistor.ts`** — обёртка над `react-native-background-geolocation`.
  **Пакет НЕ установлен.** Он платный (~$300/платформа), но
  **в debug-сборках бесплатен без ограничений** — а в сторы вы пока
  не выкладываетесь. Включить:

  ```bash
  npx expo install react-native-background-geolocation && npx expo prebuild --clean
  ```

  Фабрика в `tracking/index.ts` подхватит его автоматически.
  `metro.config.js` подменяет неустановленный пакет пустышкой — без этого
  Metro падает на статическом резолве ещё до запуска кода.

**Дрожание на месте.** Порог фильтра — не пять метров, а больший из двух:
двенадцать метров и две с половиной точности, которую сообщает приёмник.
Коэффициент обязан быть больше двух: точки на противоположных краях круга
разброса отстоят на ДВА радиуса, и при меньшем коэффициенте они проходят
фильтр по очереди — трек начинает «пинг-понг» вокруг неподвижного человека
и набирает километры за вечер. Ровно это и происходило: приложение «шло»,
пока человек сидел дома.

**Прыжки позиции.** Проверки скорости мало: при разрыве в пару минут
прыжок на километр укладывается в пешеходные 8 м/с, и трек рисует прямой
коридор через полгорода — именно это и выглядит как «меня откинуло».
Шаг длиннее 150 метров рвёт сегмент: точка принимается (человек,
вероятно, там и есть), но соединять её с предыдущей нечем — путь между
ними неизвестен.

Порядок проверок важен: скорость проверяется раньше длины шага. Поездка
на машине — это тоже длинные шаги, но её точки надо выбрасывать целиком,
иначе вдоль дороги раскроются пятна тумана, которых никто не проходил.

**Автоопределение прогулки.** Переключатель «АВТО» на карте:
`src/features/tracking/autoWalk.ts` решает по смещению от якоря, идёт
человек или стоит — ушёл на 120 метров за три минуты, значит, прогулка;
не двигался шесть минут, значит, закончилась. Правило чистое и покрыто
тестами, включая случай «сто метров за день дома»: якорь переносится,
и медленный дрейф координат прогулкой не становится.

По скорости из GPS это не делается: в городе она скачет от переотражений,
и прогулка «начинается» у окна. Смещение на сотню метров так не подделать.

Работает, пока приложение открыто. Определение движения при закрытом
приложении — ровно то, за что берут деньги в
`react-native-background-geolocation`: детект остановки и activity
recognition там на уровне ОС.

Чего не хватает в `expo-location` и что даёт платная библиотека: детект
остановки (иначе батарея сгорит за вечер), батчинг точек, автоперезапуск
после того, как ОС убила процесс, activity recognition. На Android к этому
добавляются OEM-киллеры (Xiaomi, Huawei, Oppo) — понадобится экран про
отключение оптимизации батареи.

## Как тестировать GPS, не выходя из дома

Три уровня, каждый проверяет своё:

1. **GPX-плеер в дев-панели** — вся JS-логика. Быстро, детерминированно.
2. **[Lockito](https://play.google.com/store/apps/details?id=fr.dvilleneuve.lockito)**
   (Android, бесплатно) + «Выбрать приложение для фиктивных местоположений»
   в настройках разработчика. Подаёт координаты **в систему**, поэтому
   проверяется нативный путь: foreground service, поведение после сворачивания.
   Плеер этого не проверяет.
3. **Реальные прогулки.** Запишите 5–10 GPX разного характера — город, парк,
   поездка на транспорте, потеря сигнала в переходе, «дрожание» у окна дома —
   и положите в `assets/fixtures/`. Набор реальных треков с артефактами приёма
   ценнее любого генератора; на них ловятся баги, которых не бывает в чистых данных.

Демо-фикстура пересобирается детерминированно:

```bash
node scripts/gen-fixture.js
```

## Карта и данные

Тайлы — [OpenFreeMap](https://openfreemap.org) (схема OpenMapTiles),
бесплатно и без ключа. Стиль под палитру макета собран руками
в `src/features/map/style.ts`: тёмно-коричневая земля, бирюзовая сетка улиц.
Подписей в макете нет, но на почти чёрной карте без них непонятно, где ты,
поэтому названия городов и районов оставлены, а улицы и дома — нет.

OpenFreeMap живёт на пожертвованиях и SLA не даёт. Когда понадобится
независимость: `planetiler` собирает экстракт с Geofabrik в один `.pmtiles`,
файл кладётся на Cloudflare R2 (free tier: 10 ГБ, egress бесплатный),
меняется одна константа `TILE_SOURCE_URL`.

Данные OSM под **ODbL** — атрибуция «© OpenStreetMap contributors»
обязательна и включена в стиль. Не снимайте её.

## Карта во весь экран и планета

Карта живёт на двух экранах: карточкой на главном (кнопка со стрелками
в углу) и целиком в отдельном окне `app/map-full.tsx`. Состояние у них
общее — то же хранилище и та же база, — а порядок слоёв вынесен
в `src/features/map/MapStack.tsx`: тайлы → туман → своя метка → друзья →
планета. Порядок именно там не ради красоты: два экрана с одинаковыми
слоями, набранными по отдельности, разъезжаются на первой же правке,
и в одном месте друзья оказываются под туманом.

**Планета.** При отдалении до самого края плоская карта гаснет, а вместо
неё появляется Земля — `src/features/globe/`. Это не проекция MapLibre:
нативная библиотека (в отличие от веб-версии MapLibre GL JS 5) проекции
«глобус» не умеет вовсе, в `@maplibre/maplibre-react-native` её нет.
Поэтому шар рисуется нами на Skia: ортографическая проекция
в `projection.ts`, контуры материков — Natural Earth 110m (public domain),
сжатые до 0.1 градуса и 50 КБ скриптом `scripts/gen-land.py`.

Что из этого следует:

* **Прозрачность** считается воркетом на каждом кадре жеста
  (`globeOpacity`), а геометрия шара пересобирается только когда карта
  остановилась. 4700 точек суши на каждый кадр в UI-потоке не нужны
  никому, поэтому шар доворачивается шагами по градусу.
* **Точки за горизонтом** не выбрасываются, а прижимаются к краю диска.
  Если их просто отбросить, кольцо Евразии замкнётся хордой через центр
  планеты и материк схлопнется на глазах при повороте.
* **На планете видна только своя метка.** Туман, друзья и тропа с орбиты
  не рисуются — в этом масштабе это был бы один пиксель шума.
* `minZoom` карты теперь 0 (был 10, то есть «дальше своего города
  не отдаляться»). Это и есть тот край, на котором появляется шар.
* **Кнопка с глобусом** в полноэкранной карте уводит прямо на орбиту.
  Без неё до планеты надо свести пальцы полтора десятка раз, и первый же
  живой человек решил, что планеты просто нет. По той же причине порог
  появления шара подняли: он начинает проступать уже на масштабе страны.

## Известные риски и чего тут нет

**Отставание тумана при панорамировании.** Матрица обновляется из событий
`onRegionIsChanging` MapLibre, а они не гарантированно приходят каждый кадр.
Если на устройстве будет заметный лаг — это главная вещь, которую надо
померить. Запасной вариант: рисовать туман внутри карты обычным `FillLayer`
по полигонам из `cellsToMultiPolygon` (h3-js умеет это сам, turf не нужен) —
двигается идеально, но края будут шестиугольные и без размытия.

**TextDecoder и h3-js.** `src/core/polyfills/textDecoder.ts` подменяет
глобальный `TextDecoder` на обёртку, умеющую utf-16le. Без неё приложение
падает на первом же импорте: h3-js собран эмскриптеном и при загрузке
модуля делает `new TextDecoder("utf-16le")`, а в React Native есть только
utf-8. Полифил обязан выполниться раньше остального кода — ради этого
в проекте свой `index.js` вместо `expo-router/entry` в `package.json`.
Регрессия закрыта тестом `tests/h3-boot.test.ts`.

**Туман можно выключить.** В дев-панели есть переключатель: под туманом
не видно ни карты, ни того, правильно ли легла тропа. Флаг лежит в SQLite
и раздаётся экранам через `src/core/settings/flagStore.ts` — карт в приложении
две, и читать базу в `useState` каждой из них значит оставить выключенный
туман на экране до перезапуска.

**Шрифты.** В `src/core/theme/tokens.ts` объявлены `Oswald` и `VT323`,
но файлов нет и `expo-font` их не грузит — сейчас используются системные.
Оба шрифта под OFL, скачиваются с Google Fonts, кладутся в `assets/fonts`.

## Друзья на карте

`src/features/friends/` — метки друзей и мест, где они были, поверх общей
карты. Провайдер отделён от экрана тем же приёмом, что и геолокация:
интерфейс `FriendsProvider`, за ним пока `MockFriendsProvider` — три
демо-друга, гуляющих кругами вокруг твоей точки.

**Настоящих друзей без сервера не бывает.** «Где человек сейчас» — это
обмен данными между устройствами по определению. Поэтому рядом с демо
лежит рабочая реализация на Supabase: бесплатный тариф, карта не нужна,
на двух-трёх человек лимиты недостижимы.

### Как включить живых друзей

1. Завести проект на [supabase.com](https://supabase.com).
2. Authentication → Providers → включить **Anonymous sign-ins**:
   регистрации в приложении нет, аккаунт заводится молча при первом запуске.
3. SQL Editor → вставить целиком `docs/supabase.sql` → Run. Скрипт
   идемпотентный, повторный запуск ничего не сломает. Если редактор
   ругнётся — тот же скрипт лежит разбитым на четыре части в
   `docs/supabase/`: выполняйте по порядку, между ними `0-check.sql`
   показывает, что уже создалось.
4. Project Settings → API → скопировать `URL` и ключ `anon` в `.env`
   рядом с `.env.example`.
5. Перезапустить Metro с `-c`: переменные `EXPO_PUBLIC_*` подставляются
   в бандл на сборке, без сброса кэша останутся старые.

Дальше в приложении: Профиль → Друзья → продиктовать свой код. Друг
вводит его у себя — и вы видите друг друга. Там же удаляется связь:
корзина в карточке друга сносит обе строки дружбы, а не только свою —
иначе друг продолжил бы видеть вашу позицию.

Друг — это установка приложения, а не человек: у каждой свой анонимный
аккаунт. Переустановили приложение — завёлся новый аккаунт с новым кодом,
а старая дружба осталась висеть. Так в списке и появляются «двойники».

Без `.env` всё продолжает работать на демо-друзьях, и экран честно
говорит об этом.

### Что здесь важнее кода

**Права проверяет база, а не приложение.** Правило «позицию видит только
подтверждённый друг» описано политиками RLS в `docs/supabase.sql`. Клиент
запрашивает «все позиции», а получает только доступные. Подменить запрос
в приложении, которое лежит у пользователя в руках, ничего не даст.

**Позиция уходит только во время прогулки** и не чаще, чем раз в минуту
или при смещении на сто метров (`src/features/friends/publish.ts`,
правило под тестами). Демо-провайдер тикает раз в три секунды — для
сервера такой темп посадил бы батарею за вечер.

**История перемещений на сервере не хранится.** В таблице позиций одна
строка на человека: последняя точка и время. След прогулки — совсем
другой уровень ответственности за чужие данные.

Метки рисуются в React поверх Skia-слоя, а не аннотациями MapLibre.
Аннотации живут внутри карты и оказались бы под туманом — то есть друг
исчезал бы ровно там, где ты ещё не гулял. Позиция каждой метки считается
воркетом `projectToScreenWorklet` из той же матрицы камеры, что и туман,
поэтому метки не отстают при панорамировании и не будят React.

Чего всё ещё нет и что понадобится до настоящих пользователей:

- экран согласия на шеринг с возможностью отозвать его в один тап;
- точность по договорённости: показывать другу район, а не подъезд;
- срок жизни позиции на стороне сервера, а не только в клиенте
  (`POSITION_FRESH_MS`) — иначе «был здесь вчера» неотличимо от «здесь сейчас»;
- удаление аккаунта и всех данных по запросу;
- имена: сейчас у всех «Друг», пока нет экрана профиля с вводом имени.

---

**Чего нет намеренно:** сервера, синхронизации, друзей, лидербордов,
античита, локальных пуш-напоминаний про стрик (логика `isStreakAtRisk`
готова, планировщик не подключён), реальных POI (сейчас 4 демо-места).

**Прогресс живёт только на телефоне.** Смена устройства = потеря истории.
Это осознанный выбор v1: он убирает всю инфраструктуру и заодно снимает
главный риск по приватности — история перемещений никуда не уходит.
